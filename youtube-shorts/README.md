# Выкладка YouTube Shorts

Скрипт заливает вертикальные ролики на ваш канал через официальный YouTube Data API и может открыть каждый в заданное время. Один раз подтверждаете доступ Google — дальше команда читает очередь и отправляет только новые файлы. Повторный запуск не создаёт копий.

Ролики с датой публикации можно залить пачкой заранее. В назначенный час их откроет сам YouTube, компьютер в этот момент может быть выключен.

Учебные тетради в корне репозитория этот инструмент не использует. Вся работа идёт из папки `youtube-shorts/`.

## Что считается Shorts

Отдельной галочки «это Shorts» в API нет. YouTube сам относит ролик к Shorts, если он квадратный или вертикальный и не длиннее 3 минут. Горизонтальное видео останется обычным, даже если оно короткое и в заголовке стоит `#Shorts`.

Перед отправкой скрипт читает файл через `ffprobe` и останавливает то, что в Shorts не попадёт. Удобный размер — 1080×1920. Телефонные записи с поворотом кадра тоже понимает.

Два ограничения YouTube, которые скрипт не обходит:

- На новом проекте Google даёт около 10 000 единиц квоты в сутки, а одна заливка стоит 1 600. Получается примерно 6 роликов в день. Квота обновляется в полночь по Лос-Анджелесу: зимой это 16:00 по Макасару, летом 15:00. Больший лимит запрашивают у YouTube отдельно, скрипт сам его не увеличивает.
- Пока экран согласия OAuth в статусе Testing, выданный доступ живёт 7 дней. Потом снова нужна команда `auth`. Если опубликовать экран согласия (статус In production), вход обычно приходится подтверждать один раз; Google покажет, что приложение не проверено, это нормально для личного канала.

Shorts длиннее минуты YouTube блокирует целиком, если на него есть любая претензия Content ID. Чужую музыку в такие ролики лучше не класть.

## Установка

Нужны Python 3.11 или новее и ffmpeg (из него берётся `ffprobe`).

```bash
cd youtube-shorts
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

На Windows виртуальное окружение включается так: `.venv\Scripts\activate`.

Проверка без роликов и без ключей:

```bash
python -m shorts_uploader --help
python -m pytest
```

## Ключ Google

1. Откройте [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com) и включите его в своём проекте.
2. В [настройках экрана согласия OAuth](https://console.cloud.google.com/apis/credentials/consent) выберите External, заполните название и почту. Пока статус Testing, добавьте свой Gmail в Test users.
3. В [учётных данных](https://console.cloud.google.com/apis/credentials) создайте OAuth client ID типа Desktop. Скачанный JSON положите в эту папку как `client_secret.json`.
4. У аккаунта уже должен быть канал YouTube. Если канал брендовый, на экране входа выберите именно его.

Команды ниже запускайте из папки `youtube-shorts`.

```bash
python -m shorts_uploader auth
python -m shorts_uploader whoami
```

`auth` откроет браузер. Скрипт просит два доступа: заливку видео и правку этого канала (обложка, плейлист, проверка обработки). Более узкого набора, с которым обложка и плейлист работают, у YouTube нет. Удалять ролики скрипт не умеет и никуда сам не ходит, кроме YouTube.

`whoami` печатает название канала. Если это не тот канал, удалите `token.json` и повторите `auth`.

## Очередь

Скопируйте пример и положите mp4 в `inbox/`:

```bash
cp queue.example.yaml queue.yaml
```

```yaml
timezone: Asia/Makassar

defaults:
  privacy: private
  category_id: "22"          # People & Blogs
  made_for_kids: false
  synthetic_media: false     # true, если в кадре реалистичный ИИ
  playlist_id: null

videos:
  - file: inbox/first.mp4
    title: "Как собрать очередь роликов"
    description: |
      Текст под роликом.
    tags: [shorts, пример]
    publish_at: "2027-01-15 18:00"
```

Время без пояса читается в `timezone`. Для Макасара это WITA, UTC+8, без перехода на летнее время. `18:00` здесь — шесть вечера по Макасару.

По умолчанию ролик уходит как private и на канале его никто не видит, пока вы сами не откроете его в YouTube Studio. Если указан `publish_at`, ролик тоже заливается скрытым, а в эту минуту YouTube делает его public. Отложить публикацию как unlisted нельзя: так устроен API. Время в прошлом скрипт отклоняет, потому что YouTube иначе открыл бы ролик сразу.

`privacy: public` без даты публикует ролик, как только YouTube его обработает. Для первой проверки оставьте private.

Частые категории: 22 People & Blogs, 23 Comedy, 24 Entertainment, 27 Education, 26 Howto & Style.

`made_for_kids: true` ставьте только если ролик действительно для детей. Это ваше заявление YouTube, скрипт его не угадывает.

Проверка и заливка:

```bash
python -m shorts_uploader validate queue.yaml
python -m shorts_uploader upload queue.yaml --dry-run
python -m shorts_uploader upload queue.yaml --limit 6
```

`--limit 6` оставляет запас по суточной квоте. В интерактивном терминале скрипт спрашивает «да». Для расписания добавьте `--yes`.

## Папка inbox

Можно не перечислять каждый файл. Раскомментируйте `inbox: inbox` — скрипт возьмёт видео из этой папки и вложенных. Заголовок получится из имени файла, подчёркивания станут пробелами. Рядом с роликом можно положить одноимённое описание: `clip.mp4` и `clip.yaml` с полями `title`, `description`, `tags`, `publish_at`, `thumbnail`, `playlist_id`. Строка в `videos` для того же файла важнее, чем inbox.

## Повторный запуск

`state.json` рядом с очередью запоминает контрольную сумму файла и id ролика. Тот же файл второй раз не заливается. Если заливка оборвалась после появления ролика на канале, следующий `upload` только дописывает обложку или плейлист.

Обложку (JPEG, PNG, GIF или BMP, до 2 МБ) можно поставить не сразу: для Shorts YouTube принимает её после обработки. Скрипт ждёт до 10 минут. Не успел — запустите `upload` ещё раз, второй копии ролика не будет.

Уже отправленные заголовок и описание скрипт не правит. Меняйте их в YouTube Studio. `--force` заливает ещё одну копию того же файла; старый ролик на канале остаётся.

```bash
python -m shorts_uploader status
```

## Расписание на компьютере

Когда новые файлы появляются сами, поставьте ежедневный запуск. Если ролики и так перечислены в `queue.yaml` с датами, достаточно одного `upload`: дальше YouTube откроет их сам.

На компьютере с временем Макасара это каждый день в 09:00:

```cron
0 9 * * * cd /путь/к/youtube-shorts && .venv/bin/python -m shorts_uploader upload queue.yaml --yes --limit 6
```

Планировщик заданий Windows запускает ту же команду из папки `youtube-shorts`.

## Что не коммитить

`client_secret.json`, `token.json`, `state.json` и сами ролики эта папка уже игнорирует. Ключ и токен — доступ к каналу. Не пересылайте их и не кладите в чат.
